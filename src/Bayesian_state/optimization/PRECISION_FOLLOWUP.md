# 少量候选的评分复核与近优多解

此工具接续[边界校准](BOUNDARY_CALIBRATION.md)，只复核争议最大的两组候选。
它复用正式 Scorer、共享模型和计分方法，不修改认知机制、正式默认预算或参数范围。

2026-09-19 [完整序列报告](../../../results/model_0826/precision_followup_20260919/README.md)：
S203、S301 均通过各自候选对的独立复核，差距上界分别为 .001694、.002865。
S301 粒子数翻倍后，本批候选差值的数值不确定性未减小，耗时约为原来的 2.14 倍；
因此不据此提高所有人的默认预算。384 次完整滤波计分合计约 53.10 分钟，46 项相关测试通过。
原整个入围集合及边界问题未由此自动解除。

## 固定协议

协议见 [`model_0826_precision_followup.yaml`](../../../configs/exp123/specific_models/model_0826_precision_followup.yaml)。

- S203：保留 E_C=.01 的两套解，一套同时降低 E_E，另一套保持旧 E_E。
  事先提名前一套（上轮独立复核中的第一名），用全新种子 R=256、B=64 验证。
- S301：保持上轮 M=5 的提名，与波动最大的 M=8、γ=.97 候选比较。
  同一组全新种子分别运行 R=512、B=64 和 R=1024、B=64。
  两个预算都执行；只有事先指定的 R=1024 结果用于本轮主要判断，不能挑较好的预算宣布通过。
- 总上限 384 次完整粒子滤波。最多 128 进程，每进程一个数值线程、一个进程并行层。
  S129 只读取已有概率缓存，不增加粒子滤波。

提名在任何新评分前冻结。容忍差距仍为平均 NLL .005，主判断 alpha=.05，
6000 次完整种子 bootstrap。低预算结果及配对 95% 区间仅作描述。
不同 R 使用相同种子编号，随机调用路径仍可能不同；比较不能分离出纯粒子偏差。
这些是有限 R 的近似数值诊断，不是多轮历史探索合起来的总体 95% 保证。

这是**候选对**的复核：S203 另两点、S301 另四点没有获得新预算，明确记录为排除项。
即使某对通过，也不把旧的整个入围集合自动改成“通过”，更不能称为全局最优。
到达本轮上限仍不清楚则保留 unresolved，不追加无上限的评分。

## S129 的多套参数几乎同样好，能否接受？

能接受“多个解释都符合这份行为数据”，不能直接接受“某一套是唯一真实机制”。
例如容量、记忆保持、搜索概率互相配合，可能产生近似的总拟合分数。
保存代表解和近优解，比强行挑出唯一答案更符合目前证据。
这提示实际估计存在歧义，还不足以证明模型结构上永远无法识别。

1. **描述行为：** 可以报告稳定的拟合分数及近优候选，但仍需行为拟合检查。
   新数据预测能力另需预测验证；同一份数据拟合好不等于泛化已确认。
2. **解释个体参数：** 暂不把 M=6 当成该被试确定的容量，也不把优化返回一个点
   当作参数恢复成功。参数恢复与可辨识性检查需要另外的证据。
3. **分析内部状态或关联神经数据：** 应比较近优解是否支持相同的状态结论，
   同时检查状态估计的数值精度。仅总 NLL 相近不足以保证这些结论稳健。

本工具读取 S129 两套近优解的逐试次预测，报告概率差、最高概率选项差异及
固定前后半组种子的数值敏感性。后者不是置信区间；本工具不计算潜在状态轨迹。
不要平均两套参数向量：非线性模型的平均参数不等于两种解释的平均预测。
更多计算可减少数值误差，但不能保证从相同数据中得到唯一的参数答案。

## 运行与输出

```bash
python -m src.Bayesian_state.workflows.analysis.followup_model_0826_precision --dry-run
python -m src.Bayesian_state.workflows.analysis.followup_model_0826_precision --smoke --output-dir <新目录>
python -m src.Bayesian_state.workflows.analysis.followup_model_0826_precision --output-dir <新目录>
python -m src.Bayesian_state.workflows.analysis.followup_model_0826_precision --output-dir <原目录> --resume
```

需保留协议指定的历史候选、运行清单及 S129 概率缓存；缺失时恢复原归档，不能重造历史分数。
`--smoke` 只用 S203 前 32 试次、R=2、B=2、1 进程；S129 缓存描述仍针对原完整序列。
输出包含输入/代码/缓存哈希、冻结候选和提名、每次评分的概率缓存、预算比较及 S129 描述。
续跑仅补缺失种子，拒绝覆盖已有不同结果。历史归档保持只读。
