## 已接入的优化

| 位置 | 原计算开销 | 当前处理 |
|---|---|---|
| 规则程序与编辑成本 | 每个粒子重新编译整个目录，并检查所有规则对 | 按精确目录内容及编辑成本缓存，最多8组 |
| 关系缓存键 | 每个粒子把全部几何数组转换成文本再计算哈希 | 不可变规则目录只计算一次内容哈希 |
| 功能关系数组 | 每个粒子分别计算、保存一致率及功能距离 | 同一分区的粒子共用不可变缓冲区；128粒子、152规则约节省44.8 MiB |
| 固定参考样本分类 | 已被区域覆盖的样本也投影到各类别区域 | Dykstra 直接按成员关系确定覆盖样本的类别，保留原容差、平局及距离回退 |
| 关系张量启动 | 每个新进程重新生成固定参考关系 | 独立的内容键缓存支持跨进程读取，校验后复用，原子发布新文件 |
| 一致率矩阵 | 一次构造规则×规则×样本的比较数组 | 逐行计算上三角，再对称填充；比较临时数组从2.31 GB降至最多15.1 MB |
| 粒子重采样 | 共享引擎已复制状态后，PF 再复制整份快照 | 复用共享引擎已有的复制边界；子粒子的学习缓冲区继续独立 |

功能一致率是两个规则在同一固定样本上给出相同类别的比例；功能距离为1减去该比例。
缓存保存固定的规则描述和关系数值，各粒子的规则信念、配对信念、精度及随机数状态
继续单独更新。KKT 编码保留原求解器校验，普通类别概率保留原边界投影。

## 正式拟合的时间安排

行为参数通过选择 NLL 估计，口述使用固定表达设置生成预测。参数搜索阶段可在仿真覆盖中设置：

```yaml
engine_config:
  oral_readout: null
keep_logs: false
statistics_config:
  enabled: false
```

MEG 的 coarse、fine 及 final-rescore 覆盖已设置 `oral_readout: null`，省去候选评分的口述
分布计算和输出；选择概率和NLL保持同一行为模型。固定参数仿真基配置保留共同口述设置，
选定参数后生成报告预测与轨迹。`keep_logs: false` 主要减少保存与序列化，PF 内部
仍生成既有状态诊断；其耗时需要包含在候选计时中。

现有MEG搜索配置提供128进程预算，并在同一层并行展开候选值与重复。每个坐标最多8个值，
coarse/fine的4/8次重复使就绪任务数上限为32/64；缓存命中会继续减少任务数。
被试与坐标按依赖关系推进。最终复评分按候选推进，每个候选的16次重复至多使用16个进程。
进一步提高利用率需要把独立候选的种子任务放入同一个任务池，并保持配对种子、候选顺序及
断点写入规则。该调度改造尚待实现和专门验收。

粒子数、重复次数和搜索支持决定数值误差与候选覆盖，应先通过小规模校准确定。
完整工期还取决于有效试次数、容量、实际候选数、缓存命中和机器负载；上表的倍率描述
所测单次 PF。共享源码变化会触发旧断点的内容指纹校验，新正式拟合使用新的输出目录。
