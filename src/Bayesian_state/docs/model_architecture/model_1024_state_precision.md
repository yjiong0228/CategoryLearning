# Model 1024 内部状态计算精度专项

登记日期：2026-10-28。用户授权长时计算，并要求利用128核CPU。配置为
`configs/shared/model1024_state_precision.yaml`，产物保存到
`results/model_1024/state_precision_20261028_v1`。原研究产物保留。

本轮要回答：同一组固定参数下，提高粒子数、换一批随机种子后，推断出的状态概率是否接近。
每个粒子代表一条可能的学习历史；增加粒子数扩大单次计算追踪的历史集合。
独立重复各自重新建立这个集合。两个方向分别检查，所有计算均使用完整的实际行为记录。
这里的前半批、后半批指不同随机种子的计算，真人的试次始终按原顺序全部使用。

## 案例与计算顺序

先选四个已经检查过的开发案例：S110的fc9d854123911d1a、S205的94b79a97887c62e3、
S229的a3ff7d745eb425bd、S317的c2e84ea9cd965fe2。S205是此前接近稳定的参照，
S229与S317是完整历史计算明显不稳定的困难案例；S317还包含持续执行。
每个候选固定参数、任务、刺激、选择、反馈和状态记录时点。

1. 每例以2048、4096粒子各独立计算16次，共128项。旧512、1024粒子各16次作为参照。
   旧1024采用resolution第0—7次和extension第0—7次，索引预先固定。
2. 比较同一粒子数的前8次与后8次，以及相邻粒子数的合并结果。
   另外比较2048粒子16次与4096粒子8次，用实际CPU耗时评价两种投入方式。
3. 未稳定的案例依次提高到8192、16384粒子，每级16次。
   到16384仍未稳定时，在剩余预算允许下追加到32、64次，记录追加效果。
4. 首次达到完整历史数值门槛的案例，在该粒子数下另做16次独立确认。
   确认批内部需稳定，并需与原批接近。原批与确认批分别保存。
   追加重复后若再次达到门槛，使用接下来的16个新种子确认；已经检查过的确认批保留为诊断资料。
   16384粒子的任务耗时较长，本轮在该档结果产生前登记了调度修订：每次原批加量时，
   同时排入16次使用新种子的独立确认，缩短两批串行等待的时间。原批和确认批的结果分别检查；
   原批未通过时，这16次作为额外诊断保存。后续追加原批时，再使用新的确认种子。
5. 至少两个先导案例完成独立确认，且包含S229或S317，才扩展其余13个候选。
   扩展案例先在获得先导支持的最高粒子数及其前一级各计算8次，再补到16次；
   每例独立检查，达到门槛后另做16次确认，失败则按上述粒子阶梯继续。
   先导和扩展均按登记案例顺序公平轮转；优先完成已开始的比较。

## 判定与报告

过滤只用截至本题的选择，完整历史推断还使用后续选择。二者均报告本题选择后、反馈前的状态。
独立系统的权重取决于它们赋予所用行为记录的概率；过滤权重随试次更新，完整历史权重使用整段记录。
各参数候选分别报告，参数之间暂不建立后验权重。口述不进入本轮计算。

沿用上轮工作门槛：至少8次独立计算；系统权重的有效数量至少4，任何单次权重不超过0.5。
这里的有效数量表示权重相当于多少次均匀贡献的计算。比较六个量：正确规则在场概率、
信念权重、高信念在场概率、执行概率，以及整个规则目录的信念分布和执行分布。
后两项差异为总变差距离，即所有规则概率差的绝对值之和的一半。
全部试次与这六个量合在一起，平均绝对差不超过0.025、95%分位差不超过0.10。
这组门槛同时用于重复批比较和粒子数比较；每个量的差异另列，以免汇总掩盖局部问题。
工作门槛用于数值敏感性检查，其统计覆盖率尚未校准。

完成次数和数值判断分开列出。例如，计划16次而完成15次，会报告15/16及可用结果的数值检查；
缺一次本身不等同于状态概率不稳定。正式独立确认需要计划内确认批完成，并通过上述检查。
若独立结果接近，含义是当前计算配置下有重复性；真实心理解释仍需原定的模拟真值检验。

完整历史计算还报告首题、前四分之一和中点的祖先数量：最终留下的粒子在早期究竟来自多少条
不同路径。祖先数量少提示早期信息可能缺乏数值覆盖；它与独立重复差异一起解释，单独不设通过门槛。
早期四分之一的状态差异另报，便于定位不稳定发生在什么位置。

## 预算和停止规则

从正式队列启动起，最长12小时，总预算1536 CPU小时，最多128个进程，每进程一个数值线程。
每项任务CPU上限8小时；三项运行错误触发停止检查。单一进程并行层，按可用CPU、就绪任务和内存限制并发。
内存按旧任务峰值、粒子数比例和1.3倍安全系数估计，并用新任务实测值更新；可用内存的85%作为调度上限。
实测机器为64个物理核心、128个逻辑CPU。后续任务少于64项时，调度估计会修正此前满128进程时的硬件线程共享开销，
早期保留旧低并发耗时作为下界。获得至少8次同档、并发数不超过物理核心数的实测后，
以该档最大耗时估计同档或下一次加倍的任务，避免小粒子任务中的固定开销被长期线性放大。
全程保留1.3倍安全系数和实际耗时硬上限。估计方法及实测依据单独登记。
不为填满CPU增加无分析用途的重复。先导128项预计约130 CPU小时，墙钟时间须以实际并发速度修正。

16384粒子档采用预先分配的状态数组，逐题填入原捕获器计算的数值；状态汇总每16题调用一次原汇总函数。
这种保存方式减少列表转数组时的双份历史和汇总临时数组。四例完整512粒子记录的复核均通过：
每例42个状态与选择数组逐项相等，整个状态压缩文件的SHA256也一致。
该档内存估计采用历史数组尺寸、当前规则工作区和1 GiB固定余量，再乘1.3安全系数；
新保存方式的实测峰值继续作为估计下界。数组尺寸、复核结果和启用时间保存在执行策略与修订记录中。

调度按预计剩余耗时安排任务，CPU硬上限按已结束子进程的实际资源记账与运行中进程的累计CPU判断。
全局预算终止、任务运行错误、尚未启动分别保存。CPU预算覆盖队列计算及调度；报告制作的额外耗时单列。
如果已无任务可在剩余预算和内存内完成，停止该批并登记原因。
达到独立确认标准的案例停止加量。达到最高粒子数及重复上限仍不稳定，或预算耗尽时，保留全部结果，
说明哪些量改善、哪些仍不稳定，以及仅增加粒子数是否值得继续。完整历史不稳定时，过滤结果单独评价。

本轮在8192粒子结果产生前，另登记了一次剩余预算补充安排。若自动队列因下一档任务无法在剩余预算内完成而停止，
对尚未通过独立确认的两个困难案例，在已完成的8192、4096、2048档中，选择预计能够完成的最高一档，
各增加16次独立计算，累计次数仍不超过64。只补充这一批，继续使用原12小时和1536 CPU小时上限。
它用于比较增加单次粒子数与增加独立次数的收益，独立确认的原记录保持不变。
例如4096×32与8192×16的名义粒子总量相同，实际耗时和结果差异分别报告。
补充入口为 `python -m src.Bayesian_state.workflows.analysis.model_1024_state_precision_budget --output 产物目录`；
它等待原自动队列完成，保存选择依据，再调用同一个限额调度器。总任务结束记录为`precision_completion.json`。

## 实现与复核

入口为 `python -m src.Bayesian_state.workflows.analysis.model_1024_state_precision`，
依次使用 `--phase prepare`、`--phase run` 和 `--phase summarize`。
每批通过`--cases`、`--particles`、`--systems`、`--label`登记；确认批增加`--confirmation`。
`--plan`接收多组独立计算规格，使不同案例的确认和加量共享一个队列。
自动控制入口为 `python -m src.Bayesian_state.workflows.analysis.model_1024_state_precision_control --output 产物目录`，
逐批保存判断依据，再启动登记的下一批。现有个体状态捕获器和冻结模型运行时保持原样。配置、源码、输入哈希、种子、逐项耗时、峰值内存和停止原因随产物保存。
本轮交付包括逐案例精度表、粒子数与计算成本的对照、状态曲线及早期路径保留图、明确的稳定范围和后续限制。


## 保存状态的分布检查

除原定六项概率摘要外，复用保存的粒子检查三个分布：正确规则的信念、正确规则的判断精度，
以及本题执行的规则身份与该规则判断精度的联合分布。信念沿用上一轮20个等宽区间，判断精度沿用
0至25之间的25个区间。正确规则不在场时，以一个独立类别保存其概率，保留在场概率与精度的区别。
联合分布同时保留执行规则的身份，防止不同规则的精度相似掩盖身份上的差异。

每个分布分别比较独立重复的两半与相邻粒子数，报告总变差距离的均值、95%分位数、最大值及早期
四分之一的95%分位数。它们补充解释数值稳定的范围，原定加量与确认门槛保持不变。
本分析使用已有状态数组，不重新运行模型。每个联合分布按规则身份求和后，必须与原捕获的执行分布一致；
精度各区间的概率总和必须与原在场概率一致。缓存保留源数组哈希、区间定义、源码版本和实际CPU耗时。
入口为 `python -m src.Bayesian_state.workflows.analysis.model_1024_state_precision_distributions`，
使用 `--phase cache` 生成可复用汇总，再用 `--phase summarize` 比较计算配置。
