## 参数搜索与版本选择

先使用共同Sobol离散候选，并纳入此前先导在拟合前生成的全部16个预设点；旧结果的排序
不参与候选生成。将候选投影到各简化边界；随后从每个版本的领先点作局部
搜索。嵌套复杂版本同时接收其简化版本的领先候选，防止有限搜索造成虚假的简化优势。
独立粒子系统的整段似然先求均值再取对数。后段条件似然由完整段与前段的合并似然之比
计算，保留重复系统之间的权重关系。候选选择与后段评价阶段分别保存。
同一配置若在不同粒子数下复用相同种子，先在种子内部合并似然，再跨独立种子计算数值
标准误。该分组保持原序列似然分数，避免把相关的粒子数复核视为独立重复。
跨被试复用种子时，平均评分的数值标准误按各被试标准误的平均作保守合并，保留未知相关性。

首要比较量为开发被试等权的后段每题负对数似然。优先保留在最好版本每题0.01工作容忍
以内、每个条件相对后悔不超过0.03且自主分布评分恶化不超过10%的简洁版本，并计入
数值不确定性。这些值是本轮工作决策阈值。版本尚不能可靠区分时，确定一个带明确限制的
工作版本，并保留有竞争力的替代配置。正式结果分别报告选择决定与科学支持程度。

开发后段评分产生前，另明确同参数数的简洁性顺序：先比较名义自由参数数，再比较五项
可选控制机制的保留数量，最后比较后段NLL。五项为额外执行维持、精度学习、累积失败搜索、
反馈调节保持及相似度检索。该顺序保存在`simplicity_tiebreak_registration.json`；
例如恒定保持比同为八参数的反馈调节保持少一项可选控制。所有候选仍先通过预测差异、
分条件退步和自主评分的工作容忍标准。

正式拟合前的运行标定显示，原方案的最坏计算量超过总预算。保留原协议和六项短程标定，
登记v2计算方案：共同候选48点、局部候选16点，24粒子各2次初筛，4点以96粒子各2次
确认，2点以256粒子各4次复核，必要时增加到512粒子各4次。先导的全部16点仍在共同
候选中。两个领先结构另以1024粒子各4次检查固定参数下的后段预测，再完成结构选择。
该调整使用运行时间和日程长度；调整时尚未启动正式结构搜索，也未查看模型拟合排序。

两个精度复核对象为初步最低NLL版本与满足容忍条件的最简版本；两者相同时，另取完整版本，
若完整版本已入选则取八参数版本。最终结构在这两个预选对象中确定。比较量使用平均差
加两倍标准误之和，保留共同随机数相关性未知时的保守余量。标准误采用重复系统之间的一阶
误差传播近似；有限重复下的置信覆盖率尚待校准。每个条件的平均差及自主Energy
分别通过原定保护条件。高精度复核使用相互独立的随机种子，参数保持训练前段选定的值。
结构冻结后，6名评价被试比较所选版本与完整版本；所选版本为完整版本时，以八参数版本
作为比较对象。不同粒子数差异超过每题0.01或单个重复系统占整段似然权重超过0.8时，
相应评价记录数值限制。

在评价被试结果产生前，另登记固定参数的可选数值复核。原定模型和状态恢复完成后，
若剩余预算容纳同配置实测成本的两倍及五分钟余量，则以1024粒子各4次独立运行复核
评价后段；最多48项任务并行，原计算截止时间保持不变。结构及训练选定参数保持固定。
原评分与复核评分分别保存，预算不足时记录省略原因。

自主评价使用全部路径，包含32题块正确率、反应频率、改善时点和保持等指标。条件3
分开记录种正确率、科正确率及反馈得分。已知生成模型的有限恢复检查用于区分搜索不足、
机制混淆和内部状态恢复限制；新增模拟与拟合均计入同一预算。

有限恢复检查使用每条件名单中的第一名开发被试作为刺激与知觉背景，即S110、S202、S303。
所选版本与比较版本各生成2条独立路径，共12条。每种版本以64个独立Sobol点重新搜索，
前两点以256粒子各2次确认；嵌套大模型同时接收小模型的领先边界点。生成参数另用独立
随机种子评分，以诊断搜索不足。机制比较采用完整模拟记录的似然，作为有限搜索诊断；
真人后段评价沿用其独立的数据用途。边界上等价的生成配置按最简有效结构记录。
等价检查包含精确无效坐标：容量为1时的执行维持、相似度检索及内容保持方式；
二值反馈且容量为1时的保持率；失败增益为0时的压力保持系数。条件3的配对保持继续保留。
这些等价关系在恢复数据生成之前用三条件自主路径的一致性检查确认，数值任务保持原值。
已知参数的状态恢复使用512粒子、2次独立运行，目标为当前选择之后、当前反馈之前的过滤
状态，包括内容组执行概率、内容信念、模板维度质量及条件3配对信念。区间覆盖是相关
试次上的描述性校准检查。真实潜在状态只来自模拟。

## 计算、冻结和交付

最多128个进程，每进程一个数值线程，按CPU与就绪任务数限制并行度。原方案为开始后
9.5小时停止计算、保留2.5小时交付。长记录的实测耗时及已完成的文稿编译支持将计算停止点
调整为10.5小时，保留1.5小时完成最终验证、结果整理与PDF交付；总时限仍为12小时。
该调整保存在`runtime_budget_amendment.json`，候选、粒子数、重复数与选择标准保持登记值。
CPU总预算1152小时，连续三项工作失败停止队列。每个阶段保存任务、输入、配置、源码哈希、种子、
用时及未完成原因；计算只写新结果目录。

后续队列根据已完成任务的CPU耗时优先启动预计较长的任务，以减少阶段末尾等待。
任务的参数、种子、粒子数及重复数保持登记值；原顺序、提交顺序和调度源码哈希分别保存。
数值源码在协调检出目录按原登记哈希验证后执行，独立冻结检出继续保存为参照。
结构冻结后，评价拟合与模拟恢复独立运行，各使用64个工作进程；两者总数保持128。
一个分支完成并退出其子进程后，另一分支在下一阶段可使用全部进程预算。
各分支沿用已登记的数据用途、任务和数值精度，完成标记与实际进程配额单独保存。

监管器在开发参数保存后交接，完整结果继续复用。交接将此前外部中断的全部保守CPU余量、
轮询间隔与验证交付余量显式计入新计数器，记录为`supervisor_handoff_accounting.json`。
延长计算窗口后的CPU约束由该保守计数器执行，原9.5小时方案的墙钟推算保留为历史记录。
