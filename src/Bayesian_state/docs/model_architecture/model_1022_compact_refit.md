# Model 1022：简化机制重拟合与参数恢复

## 本轮目标

本轮继续检验简洁的规则学习机制，并明确个体参数可以解释到什么程度。上一轮保留了统一在线支持的
COMPACT主干；205的固定参数对照显示，新规则继承当前活跃规则的平均精度可能改善自主学习。
本轮比较原COMPACT和加入精度继承的TRANSFER。两者分别重新估参，行为参数只使用训练段选择似然。

完整Model 1021的已有结果作为历史参照。本轮直接的共同预算比较是COMPACT与TRANSFER，两者共享
参数范围、初始候选和评分种子，得到相同的搜索机会。旧完整模型的计算预算单独列出，跨轮差异同时
包含估计流程的变化。正式默认模型保持原装配，本轮通过独立工作进程启用实验机制。

## 机制与被试

COMPACT用每条活跃规则的在线支持控制作答权重、搜索父规则和容量替换。反馈到来后保留一部分旧支持，
再加入本次反馈的证据。新规则的支持从零开始，精度使用个体初值；退出后清除该规则的支持与精度。
TRANSFER在后续新规则进入时，将当前活跃规则按支持加权的平均精度赋给新规则，之后继续原精度学习。
首题仍使用个体精度初值。该操作使已有判断精度能够跨规则延续，参数数目保持不变。

两种机制的条件1、2各有八项自由参数，条件3有九项。完整过程定义见
[前一轮研究](model_1021_simplification.md)。本轮保持已确定的任务语义、规则目录、精度更新及预测时序。

| 样本组 | 被试 | 训练／后期题数 | 开发影响 |
| --- | --- | --- | --- |
| 原开发组 | 108、205、306 | 448／192、480／224、512／256 | 行为和口述已参与机制设计 |
| 扩展组 | 110、209、309 | 288／160、352／160、512／256 | 既往影响未确定 |

两组分别汇总。后期行为只在参数冻结后评价；机制选择继续属于开发研究。口述描述当前选择的理由，
作为带噪声的内部表征检验。中点与相对读法保持既有版本，支持、冲突、未确定质量和方法覆盖率共同呈现。
口述不进入参数拟合，常规报告的低支持需要区分表达范围、报告噪声和机制偏差。

## 估计流程

每名被试的两种机制共享40个起点。起点包含同一个既有训练估计点，其余从参数支持范围中构造，
覆盖容量取值并分散抽取联合组合。随后进行两轮有上限的搜索：每轮从两个表现较好且不同的候选出发，
各检查24个单参数方向上的取值和8个双参数联合改变，共增加64个不同候选。每轮同时重新评价八个
已保存候选，其中包含原起点。每例本轮共评价168个不同参数点。

单参数方向的检查先轮流覆盖各坐标，再增加同一坐标上的其他取值。该安排使每个可变参数都获得搜索
机会。两种机制可以根据各自训练表现选择不同候选；搜索次数和评分精度保持一致。

| 阶段 | 候选 | 每次粒子数 | 独立滤波次数 |
| --- | ---: | ---: | ---: |
| 初筛 | 40 | 128 | 2 |
| 每轮追加 | 64个新点＋8个既有点 | 128 | 2 |
| 高精度选择 | 6 | 512 | 4 |
| 独立确认 | 4 | 1024 | 8 |
| 参数冻结后的行为评价 | 每机制的选中点 | 1024 | 8 |

确认阶段保留原起点和三个候选位置。选择、确认和评价使用分开的种子；同一人的两种机制使用共同种子，
便于估计差值的模拟误差。自主评价每人每机制生成128条完整路径，并保留路径分布与内部规则过程。

## 参数恢复与心理解释

本轮同时重新估计上一轮的四条模拟序列：205和306各两条。每例以既有行为拟合候选与支持范围内的
分散起点启动，再执行上述两轮搜索。旧模拟数据、原恢复结果和追加搜索结果分别保留。
生成参数单独存放，在全部估计冻结后才参与评分；候选产生过程只读取模拟行为的既有拟合记录。

生成点与估计点使用相同确认种子评分。估计点明显较差时，记录搜索不足；似然接近但参数不同，
则进一步检验有限序列的信息量、参数补偿及个体排序。存在已知零作用情形的参数单独标记。
目标规则的存在、作答贡献和精度通过原滤波被动记录，保留状态不确定性。

这四例用于检查估计方法的瓶颈。候选机制若保留主要表现，将继续用其生成数据检查参数与状态恢复，
据此确定能够解释的个体过程。机制比较综合后期选择、自主轨迹、口述支持及模型复杂度；结论明确区分
观察到的改善、可保留的设计假设和仍待验证的个体解释。

## 执行与复现

配置为`configs/shared/model1022_compact_refit.yaml`。从仓库根目录运行：

```bash
PYTHONDONTWRITEBYTECODE=1 OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
python -m src.Bayesian_state.workflows.analysis.model_1022_compact_refit \
  --config configs/shared/model1022_compact_refit.yaml \
  --output results/model_1022/compact_refit_20261022_v1
```

输出目录必须尚不存在。`--smoke`仅运行短序列、两粒子、一个数值进程的流程检查。
正式计算的16个拟合案例共用一个最多128进程的队列，每个进程运行一次滤波，数值库线程数为1。
较快的案例完成阶段后即可进入下一阶段。来源代码、数据哈希、种子、参数范围和实际版本保存在输出中。
数据与已有科研产物保持原样，新增结果使用独立目录。

初步14项测试已通过，覆盖三种条件下的候选范围、预算、共同随机方案、精度继承与状态恢复，以及
多个案例共享进程上限。短序列全流程已通过：两种被试机制均完成筛选、追加搜索、选择和确认，
一个模拟恢复案例完成冻结后的生成点评分及原滤波状态汇总。正式16例的输入计划也已核对，
两机制共享起点和种子，全部候选处于支持范围内。记录保存在
`results/model_1022/compact_refit_validation_20261022_v1/`。
正式计算已启动，输出为`results/model_1022/compact_refit_20261022_v1/`；科学结果将在完成后补充。
