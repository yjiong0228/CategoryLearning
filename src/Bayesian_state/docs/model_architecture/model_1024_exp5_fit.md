# Exp5 被试501：完整记录正式拟合协议

日期：2026-10-30。用户授权选择501开展正式拟合。本轮使用其完整128题、实际刺激顺序和
二值反馈，估计九项Model 1024参数。全部记录用于开发拟合，口述不参与参数选择。

## 模型和搜索范围

沿用已接入的62条奇偶规则、准确黑白感知、离散类别概率及共享信念与持续执行机制。
本轮修改参数估计流程，认知机制与任务接口保持迁移版本的定义。
配置为`configs/exp5/model1024_fit_501.yaml`，其中明确九项参数的离散候选值。
当错误增益为0时，失败衰减统一记为0，合并不影响行为的重复组合。

九项参数在整段记录中固定，各自作用如下。其联合影响由逐题反馈和当前内部状态决定。

| 配置名称 | 参数含义 | 在模型中的作用 |
|---|---|---|
| `p0` | 基础搜索概率 | 失败累积量为零时，决定是否探索新规则的概率。 |
| `error_gain` | 失败敏感度 | 将失败累积量转化为搜索对数优势的增量；数值越大，相同失败量越容易触发搜索。 |
| `failure_decay` | 失败累积量保留 | 一次完全成功反馈后保留的失败累积量比例，影响后续搜索率。 |
| `global_search` | 全局搜索比例 | 搜索发生时，从整个规则目录选取候选的概率；其余搜索以当前规则的局部邻域为起点。 |
| `capacity` | 活跃容量 | 同时保留并参与学习的规则数上限，含义依赖当前62条规则的表示。 |
| `retention` | 规则信念保持 | 零分反馈时旧信念的保持率；正确反馈时有效保持率为1。信念表示活跃规则的相对可信度。 |
| `beta_init` | 初始判断精度 | 首题按执行规则作答的敏感度；数值越大，越倾向选择该规则预测的类别。后续精度随反馈更新并由新规则继承。 |
| `learning_rate` | 精度学习率 | 精度更新量为反馈梯度乘以该值的10倍，决定判断精度调整的幅度。 |
| `inertia` | 执行维持倾向 | 将当前执行规则的信念乘以`exp(inertia)`，再归一化抽取下一题的执行规则。 |

对数优势是搜索概率与不搜索概率之比的自然对数，`exp`表示自然指数函数。
归一化将非负权重换算为总和为1的概率，使各规则可以按这些概率参与下一次抽取。
`failure_decay`作用于控制搜索的失败累积量，`retention`作用于规则信念。
`inertia=0`时，每题仍按当前信念抽取执行规则。搜索范围由配置中的候选值限定；
达到范围端点的估计会在结果解释中标记，域外参数的拟合表现尚未评价。

初始生成64个分散组合，包含每个容量值的基线锚点，另加入这些锚点的零持续性边界。
随后三轮各从六个不同的领先组合出发，每点最多提出12个局部、跳跃或联合改变的组合。
局部与跳跃提议分别占一半和四分之一，其余为两个坐标的联合提议。
重复组合合并；提议不足和计算未完成分别记录。

初筛使用128粒子、2个独立系统。16个候选进入512粒子、6个独立系统的确认：一半名额
优先按NLL排列，另一半保留不同参数组合。确认最好的六个候选进入2048粒子、8个独立系统
的审查。任一审查点未通过数值检查时，全部六个候选统一提高到4096粒子、8个新系统。
每个阶段使用独立种子，同阶段候选共享种子以便比较。增加计算仍未通过的点标记数值受限。

## 评分、冻结与检验

NLL表示实际选择序列的负对数概率，除以题数后便于比较。先在各独立粒子系统内累计
整段似然，再对整段似然求平均；删除一个完整系统的刀切法估计蒙特卡洛标准误。
逐题展示的选择概率使用截至上一题的证据给各系统加权，使展示与整段似然一致。

数值检查要求相邻粒子档NLL绝对差加两倍合并标准误不超过每题0.005，单点两倍标准误
不超过0.005，最大独立系统权重不超过0.9。这些阈值衡量有限计算的误差。
最终记录最低NLL候选，并按每题NLL差0.005、0.01、0.02保留工作集合。集合限于已检查候选，
统计置信覆盖尚未校准；候选概率权重和连续参数区间留待后续研究。

参数冻结后，对主工作容忍0.01内最多三个候选各生成256条完整自主路径。
反馈由各路径自己的选择与正确类别决定。全部路径用于32题块正确率、类别条件反应频率及
Energy分数；Energy衡量生成特征分布与观察路径的相容程度。自主分布不用于本轮选参。
本轮不运行参数/模型恢复或逐题内部状态验证，所得参数与过程解释保留相应证据边界。

## 预算、隔离和产物

正式队列最多运行2小时、128 CPU小时、128个单线程进程，实际并行数受可用CPU和就绪任务限制。
CPU分配为搜索48、确认16、审查56、自主生成7、汇总1小时。达到上限或三项工作进程失败时
停止提交并结束在途工作，保留完成、失败和未提交清单。完整运行与数值验收分别报告。

先用单进程短序列走完搜索、确认、审查和生成，再冻结正式输入与实际Python源码。
128题、128粒子、容量3的单次校准约18 CPU秒，队列据此预留任务成本；实际耗时由操作系统
进程账本记录。启动前测试与校准另行登记，正式预算从队列启动计时。
任务时间预留为保守CPU估计的1.1倍；CPU估计本身包含1.5倍余量。
每个工作进程在独立临时目录中的源码快照运行，快照归档与逐文件哈希保存在结果目录。
Git提交记录源码起点，实际运行身份以快照哈希为准。

2026-10-30的首轮运行使用共享队列原有的2倍时间预留。在2048粒子检查结束后，
这一预留启动了8项4096粒子任务，将另40项留在队列中。
补算入口`model_1024_exp5_complete`用新的1.1倍时间预留承接原队列已无法启动的任务。
原进程负责已启动任务，补算只提交其余任务，两边按候选合并成完整独立重复组。
候选、种子、模型源码和数值阈值保持登记定义。

补算沿用首轮的总截止时间。其CPU额度从原128小时上限中扣除原运行的保守剩余上界：
已消耗CPU、在途进程完整CPU限额、原自主生成额度及余下时间内一个协调进程的CPU。
两边预算与任务归属记录在`supplement.json`，原结果完整保留。
后续运行若仍有部分升级任务未完成，会保留上一档完整候选集合，并标记计算未完整完成。

候选及数值检查；`best_engine.yaml`与`best_predictions.csv`提供最低NLL点的模型配置和
拟合内条件预测。`report_v1/report.md`汇总参数、生成分布及限制，全部路径和逐题概率保留。
