# Model 0923：连续规则使用的定向检验

## 问题与本轮候选

208的容量交叉对照显示，容量从4增至6时，正确规则被保留得更稳定，末段作答贡献却下降约0.11–0.13。
对应参数的信念保持率γ为0，反馈后的规则支持主要反映最近一次反馈。
本轮检查：把历史证据持续用于集合内信念，能否改善正确规则在场后的使用。
前序证据见[容量与提议概率的独立作用](model_0923_reentry_precision.md#容量与全局提议概率的独立作用)。

本轮采用三个明确的计算时机。BASE沿用原信念更新；ENTRY只在新规则实际入场时回顾历史；
CONTINUOUS在每题规则集合确定后回顾历史，包括没有新规则入场的题。
ENTRY与CONTINUOUS采用同一历史评分、同一基础规则权重和同一执行惯性。
两者的差异是历史评分何时进入集合内信念。所有方案均保持RETAIN精度存储机制。

## 从历史证据形成当前信念

在第t题形成回答前，模型已经完成前t−1题的反馈处理。先按原H流程确定活跃集合Aₜ，
再计算集合内规则的历史支持。每条历史包含当时的知觉刺激xᵢ、回答aᵢ和反馈fᵢ；
条件3还保存当时反馈前的配对信念πᵢ。历史评分使用共同参照精度β₀，即现有精度初值。
历史保持率δ沿用H的参数。

历史支持是各题相对机会水平的对数反馈似然的加权和：

\[
s_{h,t}=\sum_{i=1}^{t-1}\delta^{t-1-i}
\log\frac{p(f_i\mid x_i,a_i,h,\beta_0,\pi_i)}{p_0(f_i)}.
\]

h表示一条规则，p₀表示对应反馈的机会概率。这个比值大于1时，该题支持这条规则；
小于1时，该题降低它的支持。条件1、2沿用各自的类别反馈似然，条件3使用经验发生时保存的配对信念。
本题刺激、回答和反馈尚未进入这一历史和。

随后从固定基础权重bₕ和历史支持形成活跃集合内的信念：

\[
q_{h,t}=\frac{b_h\exp(s_{h,t})}{\sum_{j\in A_t}b_j\exp(s_{j,t})},
\qquad h\in A_t.
\]

集合外的信念为0。归一化使集合内权重之和为1。每次重建都从基础权重和历史和出发，
每条反馈在本次历史和中只出现一次；此前累积的规则后验在这一步被新计算的q替换。
执行惯性继续提高上一主导规则的相对权重，各规则依照已经学到的当前精度预测类别，
这些预测再按作答贡献混合。

这里的q描述被试的规则信念。粒子权重继续用于研究者根据真实选择推断潜在状态。
两类权重的职责和更新时间保持分开。

普通反馈更新仍在回答后执行，其后验参与下一题的退出和搜索父规则选择。
因此，γ仍可通过这些决策影响过程。重建信念的方案关闭了新规则的亲和度转移通道，
`transfer_scale`在ENTRY与CONTINUOUS中保持输入记录，解释其心理作用时按关闭通道处理。
这一候选还明确假定：历史回顾使用β₀，当前类别预测使用各规则已经学习的精度。

计算缓存只保存可由已完成历史重新得到的和。重复读取同一历史头不增加证据；新增反馈到达后只追加新项，
并对旧和施加相应折扣。缓存与不可变历史一起进入粒子状态，克隆后继续使用同一数学定义。

## 208的固定参数结果

POOL与SEARCH分别使用容量4和6、基础全局提议概率0.2的两个参数点，其余12个参数固定。

所有路径在原576题刺激顺序上，用自身回答取得反馈。原行为选参结果保持冻结，口述未进入本轮计算。

共同初始精度的历史回顾，在这组参数下进一步削弱了正确规则的贡献。每题重建比仅入场时重建的生成表现更差。
当前结果把这一具体实现保留为诊断对照。新机制的参数尚未重新估计，选择似然与口述尚未评价。

下一项值得区分的是历史证据采用哪种精度。当前回顾始终使用β₀=1，而正确规则末段实际精度约为22。
H已经另行保存按经验发生时的规则精度积累的证据，用于退出判断。
下一原型可将这份证据用于集合内信念，并在新规则入场时承接共同历史准入所得的初始证据。
它将检验按学习过程实际精度积累的支持能否帮助持续使用。两种证据来源的作用尚待对照验证。

## 实现、验证与复现

机制为[连续回顾信念](../../model/modules/hypothesis_transition/continuous_recalled_belief.py)，
通过实验上下文启用，原模型配置行为保持原样。运行入口为
`src.Bayesian_state.workflows.analysis.model_0923_continuous_recall_probe`，配置为
`configs/shared/model0923_continuous_recall_probe.yaml`。

```bash
python -m src.Bayesian_state.workflows.analysis.model_0923_continuous_recall_probe \
  --config configs/shared/model0923_continuous_recall_probe.yaml \
  --output 新结果目录
```

加`--smoke`只运行一个参数点、一个种子、16题和一个工作进程，包含关闭、仅入场和每题三种时机。
完整运行使用132个任务、最多64个单数值线程工作进程，其中4个任务重放关闭候选的原路径。
四条完整重放在全部输出数组上与原保存路径逐值一致。

三种实验条件的历史时点、旧ENTRY实现对应与克隆继续运行均已检查，10项机制测试通过。
完整CONTINUOUS计算重建147,200次信念，其中88,783次没有新规则入场；
每次使用的历史长度都等于已经完成的题数。ENTRY共重建57,981次，均伴随新规则实际入场。
独立验证重算21,636项数值、2304次完整路径删除评分，核对1279项输入哈希，并再次验证四条完整基线重放。

生成目录为`continuous_recall_probe_20261018_v1`，
[评分与逐路径表](../../../../results/model_0923/continuous_recall_summary_20261018_v1/scores.csv)
位于`continuous_recall_summary_20261018_v1`，独立验证为`continuous_recall_validation_20261018_v1`。
这些结果描述一名开发被试的固定参数机制筛查；当前结论限于本轮参数和共同参照精度假设。
