# exp4：Model 1024 观测与概率反馈接入

`model1024_inputs.yaml` 登记401、402、403三名被试的输入文件和字段约定。
输入准备与小规模闭环入口共用这些观测序列，模型的信念、搜索、精度和持续执行机制沿用共享实现。
输入检查使用实际选择和实际二值反馈。被试在任务开始前已被告知反馈具有概率性；
该事实作为实验元数据保存，具体概率知识及指令如何影响初始不确定性预期留待机制比较。

## 准备输入

从仓库根目录运行，`--output` 必须是尚不存在的目录：

```bash
python -m src.Bayesian_state.workflows.runs.prepare_model_1024_exp4 \
  --config configs/exp4/model1024_inputs.yaml \
  --output results/model_1024/exp4_inputs_20261028_v2
```

默认核对配置中的全部被试；`--subjects 401` 可限定为一人。命令只读取数据并保存输入包，
闭环检查使用下述独立入口，正式拟合和参数／状态恢复分别安排。

每人的三个文件如下：

| 文件 | 内容与用途 |
|---|---|
| `observations.npz` | `stimulus`、`choices`、实际 `feedback` 和原始 `presskeys`；模型观测使用前三项 |
| `task_metadata.npz` | 原始刺激表的完整精度 `target_probs`、行为表的三位小数 `recorded_target_probs`、原试次标识、原数据行号、刺激编号及两套模糊标记 |
| `metadata.json` | 特征顺序、知觉阈值、按键映射、session边界、来源哈希和标记差异 |

总目录的 `manifest.json` 保存完整输入配置、文件哈希、实际Python及依赖版本，
状态为 `inputs_validated`。它表示输入核对通过，模型执行状态单独记为 `not_run`。
来源文件的SHA-256哈希用于检查之后读取的文件是否与本次相同。

## 时序、反馈和特征坐标

每名被试形成一条按 `iSession, iTrial` 递增的完整历史。加载器检查源记录顺序和唯一性；
出现乱序或重复标识时报告错误。`iBlock` 原样保留。session边界由零起点、左闭右开区间表示，
例如401的第一场为 `[0, 320)`，第二场为 `[320, 640)`。
同一模型实例跨session继续接受观测，活跃规则、信念、精度、执行身份和随机流持续演化。

`choice` 使用类别编号，`presskey` 来自原始行为表。加载器按原试次逐项核对选择和反馈，
并检查整段按键映射的一致性。概率较高的选择仍可能收到负反馈；这类试次完整进入学习序列。
实验概率存入任务元数据，供后续环境抽样和评价使用。学习者每题接收刺激、实际选择和实际反馈。

四个特征保持各被试数据中的颜色顺序：401为绿、黄、粉、蓝；402为绿、粉、黄、蓝；
403为黄、绿、粉、蓝。知觉模块显式使用 `noise_mode: uniform`，从exp4的
`Task1b_errorsummary.csv` 读取阈值。共享知觉实现对同一颜色的各level取平均，
再按该被试的特征顺序排列，得到均匀知觉误差的半宽。输入接入会核查阈值完整性和排列结果。

库接口位于 `src.Bayesian_state.simulation.exp4_data`：

```python
from src.Bayesian_state.simulation.exp4_data import load_exp4_subject

case = load_exp4_subject("configs/exp4/model1024_inputs.yaml", 401)
observations = case.observations()
context = case.model_context()
# 在已安装Model 1024共享机制的运行环境中，用context创建一个模型实例，
# 将observations整段传入fit_step_by_step；知觉模块显式配置noise_mode="uniform"。
```

`arrays.categories` 为 `None`，`arrays.target_probs` 保留原始刺激表中的概率。
现有部分1024研究入口按确定性类别核查反馈；exp4闭环使用下述概率反馈入口。
当前配置用于观测准备，已有 `pmh_prob_proto` 配置保留其原模型与用途。

## 小规模概率反馈闭环

`model1024_smoke.yaml` 使用401前32题、8个粒子、4条自主路径和1个worker。
参数为明确登记的接口示例值。完整解析配置随输出保存，包括保持率0.8、执行惯性2、
初始精度5、精度学习率0.1及共享规则相似度的100000次固定抽样。
模型装配继承 `model_0923_cond1_full_v3.yaml`，运行时组合1024已有机制。

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
python -m src.Bayesian_state.workflows.runs.run_model_1024_exp4 \
  --config configs/exp4/model1024_smoke.yaml \
  --output results/model_1024/exp4_closed_loop_20261028_v1
```

每次运行使用新目录。入口预算限制为至多64题、16粒子和8条路径，配置固定一个worker。
观测路径按真人历史逐题更新，保存当前选择发生前的预测概率；反馈直接取实际记录。
自主路径从初始状态出发，先根据自身状态抽取选择，再由环境根据所选类别抽取反馈。
两条路径共用1024机制与参数。环境按原始刺激表的完整精度概率运行：
每题抽取一个均匀随机数，随机数小于所选类别的概率时返回1，否则返回0。
知觉、规则转换、选择和反馈各有独立随机流，相关种子保存在输出中。

模型反馈似然沿用 `category_feedback`，精度沿用反馈梯度和ADD10更新。
奖励仍参与结果依赖保持、失败积累与搜索、新规则初始信念份额和精度学习。
“已告知反馈具有概率性”保存为实验元数据；当前运行尚未按这条指令调整模型的初始信念。
机制是否足以解释exp4需要后续行为与模拟验证。

| 输出 | 内容与时点 |
|---|---|
| `observed.npz` | 真人刺激、选择、实际反馈；作答前类别概率和粒子有效样本量、重采样标记 |
| `task_metadata.npz` | 完整精度任务概率、原试次标识、源行号及刺激编号 |
| `autonomous_000.npz` 等 | 每条完整生成路径、作答前选择概率／规则信念／精度、反馈后信念、所选类别的奖励概率和反馈抽样值 |
| `manifest.json` | 解析配置、种子、数据与代码哈希、依赖版本、检查结果及逐路径指标 |

评价分别保存较优选择比例、正反馈比例、所选类别的期望奖励及其与最优期望奖励的差距。
两类等概率时，两种选择都计为最优。所有已执行试次均计分，包括首题。
观测选择负对数似然由共享 `choice_nll_loss()` 计算，给定真实过去选择和反馈，参数固定为示例值。
运行时重复一次相同种子的观测滤波，并用生成选择与反馈逐题重放每条路径，
检查预测、知觉、信念和精度完全复现。反馈抽样与概率归一化也在保存前检查。

本入口固定实际刺激前缀和记录长度；session之间状态延续。
自适应刺激安排、实验停止规则、完整学习时长分布和参数估计尚待接入。
`closed_loop_smoke_passed` 表示接口和上述数值检查通过；模型适合度、参数与状态可恢复性需另行验证。
